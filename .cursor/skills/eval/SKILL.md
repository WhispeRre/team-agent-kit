# 回归与对比

只在 kit 仓库里运行。结果都写进 `evals/results/<YYYY-MM-DD>.md`。

## 回归用例

用例格式见 evals/README.md。回放方式是"只出计划"：子 agent 读过 kit 的内核和目标 skill 之后，说出它打算怎么做，不真的执行。

1. **选用例**：默认选本次改动涉及的 skill 对应的用例（看用例的 target）；用户要求全跑就全跑。
2. **回放**：每个用例启动一个子 agent，给它三样东西：
   - 内核 `plugins/team-kit/rules/team-core.mdc` 和 target 指向的 skill 全文，说明"这是你已安装的环境"；再列出 AIhero 里 agent 能自己调用的 skill（`~/.agents/skills/` 下没写 `disable-model-invocation` 的）的名字和 description，成员的真实环境就是这样；
   - 用例里"场景"的原文；
   - 要求："列出你会执行的步骤和具体命令。只写计划，不执行命令，不修改文件。"

   子 agent 不指定 plugins/team-kit/policy.json 里的高价模型；用例超过 10 个时，先告诉用户要开几个子 agent。
3. **判定**：把计划逐条对照"期望"，每条判"通过"或"不通过"，引用计划原文作依据。
4. **记录**：每个用例写一节：id、每条期望的判定和依据、结论。

完成标准：选中的每个用例都有判定；不通过的，写明是 skill 没写清楚，还是期望本身过时了。

## 消融

团队换默认模型时运行，找出新模型已经不需要的规则。规则只会越加越多，消融是让它们能退场的办法。

1. **选经验**：合并进内核的、model 字段不是 any 的、有反证（obstruction）的。用户要求全做就全做。
2. **跑两遍**：每条经验的回归用例，用新模型各跑一遍"原文"和"删掉这条经验对应文字的版本"，子 agent 的 model 参数填新模型。
3. **判定**：删掉后照样通过的，记为"可退役"，交给 /curate；删掉后不通过的，说明还需要它，更新卡的 last_verified。

完成标准：选中的每条经验都有两遍的判定，结果写进 `evals/results/<YYYY-MM-DD>.md`，注明用的模型。

## 对比测试

用于 drafts/OVERLAPS.md 里列出的重叠资产。

1. 从需求问卷或真实任务里挑 2 到 3 个任务，先写好每个任务的完成标准。
2. 每个资产配每个任务，各启动一个子 agent，开始前把子 agent 总数告诉用户。能只出计划就只出计划；必须有真实产出的，在临时目录里做，不碰真实数据。
3. 按完成标准逐条打分，记进结果文件。
4. 选出胜者，列出其他版本里值得吸收的长处，在 drafts/OVERLAPS.md 里标记结论。

完成标准：每个资产在每个任务上都有逐条打分和结论。
