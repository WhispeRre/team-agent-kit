# 工作流用 AIhero 原版，kit 只做团队层

团队要的是每个新项目都按同一套规则和工作流产出高质量的结果，同时内核要薄，免得今天的规则在模型变强后变成阻碍。

我们不自己写主流程，直接用 [AIhero 的 skills](https://www.aihero.dev/skills)（mattpocock/skills）原版，用 `npx skills` 安装。它已经有一条按任务大小分岔的主流程（访谈澄清、规格、拆票、实现、两线验收、复盘）和一个导航 skill（/ask-matt），并且一直有人维护。kit 只补它没有的团队层：内核里的边界和红线、花费守卫和其他 hooks、经验卡的跨人汇总，以及每个项目的验收标准（`CODING_STANDARDS.md`，其中的团队基线由 /kickoff 从 kit 同步，AIhero 的 /code-review 会自动读它）。

不复制一份 AIhero 进 kit，否则会断掉它的更新；也不改原版，否则成员更新时改动会被覆盖。团队的调整只写在团队层。

代价：

- AIhero 是英文、偏写代码。飞书表、外联、3D 这类任务主要靠内核、验收标准和团队自己的 skill。
- 外部依赖会自己变。负责人先更新、跑回归，再通知大家更新，否则成员之间的版本会不一致。
- 有几个 AIhero skill 会批量开子 agent，内核的【需确认】照样适用，用户自己调用时多一次确认。
