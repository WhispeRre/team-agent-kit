# 验收标准

交付前和审查时对照这份文件。文件名沿用 AIhero 的约定，`/code-review` 会自动把它当作 Standards 一线的依据。只写需要判断的标准；能用 lint、测试或脚本查的，做成检查。

## 团队基线

由 /kickoff 从团队 kit 同步；要改这一节，写成经验卡走 /promote。

- 密钥、token、密码不出现在代码、文档、日志和输出里，只写它放在哪（环境变量名，或已 gitignore 的文件）。
- 客户和合作方的个人信息用代号，或写"见某表某列"。
- 脚本和命令说明在 macOS 和 Windows PowerShell 上都能用；只能在一边用的，写明原因和另一边的做法。
- 花费跟任务大小相称：skill 和脚本里不写死高价模型；批量调用付费接口、批量写入共享数据的脚本，支持先只跑几条样本。
