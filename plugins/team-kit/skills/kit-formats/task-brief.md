# 任务简报

```markdown
## 任务简报
- 目标：<一句话，说清给谁、解决什么>
- 完成标准：
  1. <可检查的条件>
  2. <可检查的条件>
- 约束：预算 <金额或额度>；截止 <时间>
- 不可逆操作：<花钱、对外发送、覆盖或删除共享数据的步骤；没有写"无">
- 相关经验：<经验卡 id；没有写"无">
```

## 好的完成标准

能由第三方直接核对，不靠感觉。通常是下面四种之一：

- 一个数字："飞书表 Ready 页写入 3168 行，B 列全部是'未联系'"
- 一个可运行的检查："`npm test` 通过"、"脚本输出 `EMAILS_DONE 3168`"
- 一份抽样："每类各抽 1 封邮件给用户看，用户确认开场句和中间句说的是同一件事"
- 一个存在性事实："`dist/` 下生成 index.html，浏览器打开无报错"

"做得好一点""尽量完善"这类说法，换成上面某一种；换不了就继续问。
