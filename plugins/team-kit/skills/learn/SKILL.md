# 复盘

把会话里的**信号**变成经验卡，再分拣到它该去的地方。下文的 `<kit>` 指本 skill 目录往上两级（插件根目录）。

信号有五种：

- **纠正**：用户指出做错了，或要求换一种做法。如果 agent 是照 kit 的规则（内核、团队 skill、hook 守卫）做的，比如用户嫌确认太多、步骤太繁，那就是这条规则的反证，见第 3 步。
- **失败后修正**：工具报错或命令失败，后来找到了能用的做法。
- **重复**：同一串手工步骤在一次或多次会话里反复出现。
- **缺信息**：花了很多轮才找到某个文件、配置或事实。
- **高消耗**：投入和任务大小不相称，比如小改动也全量扫描整个仓库、一次开一批子 agent、用了高价模型（清单在 `<kit>/policy.json`）。这类会话往往没人纠正、也不报错，只能从消耗上看出来；证据来源写 `outcome`。

## 1. 定范围

默认复盘当前会话。用户要复盘"最近几次""这周"时，运行
`node <kit>/scripts/stats.cjs --workspace <项目根目录> --list <N>`
拿到这些会话的 transcript 路径。子 agent 多、标了"用了高价模型"或"拦下"的会话优先读。脚本不存在，说明只装了 skills、没装插件，那就只复盘当前会话。

完成标准：知道要读哪些会话。

## 2. 找信号

逐个读 transcript，把五种信号全部列出来，每条附一句原话或报错摘录；高消耗附上规模（扫了多少文件、开了几个子 agent、用的什么模型）。会话里跑过 AIhero 的 /retro 的，它提的改进也列进来。

完成标准：每个会话都读完，每条信号都有摘录。

## 3. 写卡

按 `kit-formats` skill 的经验卡格式处理每条信号：

- lessons/ 里已有讲同一件事的卡：追加一行证据，更新 last_verified。
- 没有：新建一张，status: inbox。
- 反证：在 `<kit>/lessons/` 找到那条规则的卡，在项目 lessons/ 建一张同 id、同标题的卡（status: inbox），证据来源写 `obstruction`；分拣时选团队级，/promote 后会追加到团队那张卡上。规则没有卡（比如内核里原有的条目）时，新建一张卡，标题写放宽后的规则。
- 问题只在某个模型上出现（换个模型就没有）：在 model 字段写匹配模型名的正则，比如 `sonnet`。会话用的模型见 `stats.cjs --list` 的输出。
- 不值得记的（一次性笔误、用户临时改主意）：在汇报里写一句理由。

完成标准：每条信号要么落到一张卡上，要么有不记的理由。

## 4. 分拣

把 status: inbox 的卡逐张给用户选去向（有提问工具就用，每张卡一个问题）：

- **项目级**：status 改为 accepted，按类型落地（见下）。
- **团队级**：level 改为 team，status 改为 accepted，之后用 /promote 提交。
- **改 skill**：问题出在项目或团队自己的 skill，给出具体修改；团队 skill 的修改按团队级处理。问题出在 AIhero 的 skill：不改原版（更新时会被覆盖），把团队的做法按项目级落地，或按团队级提交。
- **拒绝**：status 改为 rejected，在"说明"里写原因，以后去重用。
- **先放着**：保持 inbox。

项目级经验按类型落地，只有查不到的事实才常驻在 AGENTS.md：

- **机械的**（固定的命令写法、参数、文件位置、某类报错的解法）：卡上补 trigger，会花钱或改数据的再加 `enforce: ask`，hook 在命中时提醒或拦下确认；能用 lint、测试或脚本查的，提议在项目里加上。
- **判断的**（什么算好、容易判断错的地方）：在 CODING_STANDARDS.md 的"本项目"加一行 `- <标准>〔<id>〕`，交付和审查时对照。
- **查不到的事实**（真实数据在哪、要用哪个账号）：在 AGENTS.md 的"已知坑"加一行 `- <事实>〔<id>〕`。

限制某个模型的团队级经验，在卡里写明模型名：负责人整理时把它加进 policy.json 的高价模型清单，之后 hook 会拦下用它的子 agent。

完成标准：每张 inbox 卡都有去向；`node <kit>/scripts/check-project.cjs <项目根目录>` 没有错误。

## 5. 结晶

看"重复"信号：同类任务做到第三次，提议写成 skill（放在项目 `.cursor/skills/<名字>/`）；skill 里稳定不变的步骤，提议固化成脚本。只提议，用户同意再做。

## 6. 汇报

几句话说明：读了哪些会话、找到几条信号、写或更新了哪些卡、各去了哪、有什么结晶建议。最后运行 `node <kit>/scripts/stats.cjs --workspace <项目根目录>`，附上本项目的会话指标。
